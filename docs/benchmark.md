# آزمون ظرفیت داخلی

اجرای نهایی: ۱۰ اکتبر ۲۰۲۶، PHP 8.4.24 / WP 7.1.3 / WC 11.2.1 / AS 4.1.0 / MariaDB 11.8.6، یک worker محلی. اعداد ماشین‌خوان در benchmark-results.json ثبت شده‌اند.

| اندازه / نتیجه | مقدار |
|---|---:|
| محصولات واقعی WooCommerce محلی | ۲۰۰۰ |
| کارهای واقعی Action Scheduler در چهار دور | ۸۰۰۰ |
| complete / failed در بازه ID نهایی | ۸۰۰۰ / ۰ |
| snapshot مشترک شبیه‌سازی‌شده (۲۰۰ canonical × ۴) | ۸۰۰ |
| HTTP واقعی / تغییر قیمت | ۰ / ۰ |
| زمان worker بر اساس log UTC | ۹۲ ثانیه |
| latency callback p50 / p95 | ۵ / ۱۱ میلی‌ثانیه |
| حافظه peak کل harness شامل آماده‌سازی | ۲۴۹٬۱۵۱٬۴۸۸ بایت، حدود ۲۳۸ MiB |
| CSV validation: ۲۰ chunk صدردیفی | ۲٫۲۷ ثانیه |
| CSV apply: ۴۰ chunk پنجاه‌ردیفی | ۱۸۲٫۷۷ ثانیه |
| اندازه تقریبی جدول‌های افزونه قبل/بعد | ۴۷٬۹۸۸٬۷۳۶ / ۶۷٬۲۳۹٬۹۳۶ بایت |

حافظه peak مخصوص یک callback جدا اندازه‌گیری نشده؛ برای سقف کل روند گزارش شده است. اندازه InnoDB بر اساس information_schema تقریبی و متأثر از اجراهای قبلی است؛ پیش‌بینی رشد production نیست. ۸۰۰۰ proposal مستقل ساخته شدند؛ sharing فقط snapshot منبع را مشترک کرد. sentinel صف گروه دیگر pending ماند. Worker با `--hooks=vsp_benchmark_poll` فیلتر شد و cron/async محلی برای جداسازی آزمون غیرفعال بود؛ این شاهدِ اجرای بار همزمان واقعی سفارش/پرداخت نیست.

### خطاهای مشاهده‌شده و اصلاح

اجرای اولیه ۸۰۰۰ کار را runner پس‌زمینه‌ای برداشت که callback آزمون CLI را نداشت؛ آن کارها failed شدند و از نتیجه ظرفیت حذف شدند. سپس async فقط در MU plugin محیط local خاموش شد. CLI گروه AS 4.1.0 با وجود گروه دیتابیس، خطای resolution داد؛ مسیر hook filter آزموده و در cron.md ثبت شد. همچنین CLI غیرتعاملی در پایان «0 scheduled tasks completed» نمایش داد؛ نتیجه از statusهای واقعی DB و شمارنده مستقل callback، نه این متن، تأیید شده است.

در بازپخش CSV، lock-table deadlock دیده شد. lease محصول پیش از transaction تنظیمات گرفته می‌شود؛ mapping و cursor در transaction هر ردیف ثبت می‌شوند و retry محدود DB وجود دارد. import ناقص از cursor ادامه یافت و اجرای نهایی تازه کامل شد. rollback تراکنش و retry با crash تزریق‌شده نیز آزمون یکپارچه دارند.

### بازتولید

فقط روی محیط local ساخته‌شده با tools/setup-runtime.sh، بدون آزمون همزمانی که تنظیمات سراسری را تغییر دهد، `bash tools/benchmark.sh` را اجرا کنید. اولین بار داده محلی می‌سازد؛ اجراهای بعد CSV و ۸۰۰۰ کار تازه را بازپخش می‌کنند. اسکریپت verify کامل‌بودن DB، ثابت‌ماندن قیمت‌ها و sentinel را الزام می‌کند. fixture خارج ZIP نصب است.

این آزمون **ظرفیت داخلی** را نشان می‌دهد؛ ۸۰۰۰ HTTP در روز، محدودیت تجاری ترب، هزینه منبع یا پایداری چندروزه را اثبات نمی‌کند. نمونه واقعی دریافت محدود و جدا در data-feasibility.md گزارش شده است. بدون داده معتبر و ظرفیت مجاز، افزایش بودجه یا اجرای خودکار توصیه نمی‌شود.
