# Architecture and operational contracts

Runtime: WordPress + WooCommerce, PHP 8.1+, 64-bit integer PHP, InnoDB. Tested versions are in the test report; other combinations remain unverified. No Composer dependency, separate Action Scheduler copy, browser or external worker is required on the shop.

`ProviderRegistry -> FetchClient -> TorobProvider -> immutable snapshot -> ProposalService -> PricingEngine -> PriceApplier -> WooCommerce CRUD`

Only PriceApplier writes prices. Activation starts in monitor mode with sources disabled. A poll in monitor mode persists a snapshot and status, never applies prices. Providers never mutate products. Inventory, orders, customers and storefront markup are untouched.

Money is integer 0.01 IRR (`IRR × 100`, `IRT × 1000`), bound 10^12 minor units. Parsing accepts explicit decimal strings and Persian/Arabic digits; ambiguous grouping and floating point inputs are rejected. Profit calculation distinguishes margin on sales and markup on cost. Tax basis is the WooCommerce stored price basis; cost must be the complete cost in that same basis, including nonrecoverable charges once. No automatic tax or fee double counting is performed. Fee bps are a percentage on sales; dynamic floor is rounded upward. With sales fee f, margin floor is C/(1-m-f), while markup floor is C*(1+r)/(1-f). Proposal and rollback share the same profit-floor calculation, including future/unknown cost time rejection.

Matching requires a manager-confirmed link and exact equality of all configured attributes per offer. Quality/model are mandatory; unknown does not equal a match. Self exclusion uses exact normalized host or verified store ID. Ambiguous identity holds execution. Shipping is not included; null is never zero.

Each mapping references an immutable content-hashed rule plus an independently versioned match. RuleResolver exposes product -> explicit group -> category priority -> brand priority -> default precedence and rejects equal-priority ties. This release uses product rules plus schedule/age groups; category/brand inheritance and dependent variations are not connected to the UI.

Snapshots are keyed by canonical source + five-minute window. Product proposals include snapshot, rule version, match version and current product hash. Execution recalculates with current source age, bounds, currency, manual lock, inventory, sale policy, mode, pause and daily cumulative delta. A final WooCommerce pre-save guard rechecks pause and price hash. Product and source leases use conditional database insert/update and owner-specific release.

An intent is persisted before CRUD. Crash after save reconciles the exact after hash without another write. Crash before save cancels intent and requires recalculation. A changed state becomes a conflict. Rollback has its own deterministic ID and only restores when current regular/sale/effective/dates/stock/type/parent exactly match the recorded after state; current bounds and dynamic floor also apply. Default sale policy is to hold. Existing active-sale writes require an explicit `write_mode=sale` rule and never create a discount or erase dates. Regular mode refuses any active or scheduled sale.

**External writer limit:** WooCommerce CRUD offers no cross-plugin compare-and-swap price API. The plugin lease coordinates its own workers; hooks/hash rereads catch common external edits, but another writer can commit in the narrow interval after the final guard and before persistence. We do not claim universal atomicity against plugins that bypass hooks or write concurrently. Such stores require a coordinated single writer and a staging pilot; automatic deployment is blocked by source validation in this release.

Action Scheduler group is `viratel-smart-pricing`; keyset dispatch handles 50 mappings, imports validate 100 rows and apply 50 rows per task. Jitter spreads work. Actual HTTP attempts (including redirects) reserve budget before sending and are counted independently of products/jobs. Retry is capped at 3 with backoff and Retry-After; circuits open on 403/429/challenge or repeated failures. A ten-second spacing is a conservative default, not proof of Torob throughput. Budget clocks are UTC calendar day/month; quiet-hour selection uses the site timezone.

CSV never writes prices. A mandatory asynchronous dry-run resolves IDs/SKUs, duplicates, links, units and qualities. Apply uses an optimistic mapping hash and transaction per row, recording previous mappings and an import marker. Repeated chunks continue from the saved cursor. Configuration rollback is distinct from price rollback, uses product leases and refuses subsequent mapping versions. InnoDB is required for row+cursor atomicity.

Security: custom view/manage/apply caps, nonces separate from authorization, REST permission callbacks, escaped output/prepared SQL, strict HTTPS Torob product-only allowlist, WordPress safe transport, redirects revalidated for host and canonical ID, 1MB response/15s timeout and TLS verification. Tracking links are never followed. No secrets are collected. Test replay is outside the install ZIP; test price writes require the test harness constant and a local environment, never an admin checkbox.
